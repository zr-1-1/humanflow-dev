# HumanFlow 任务目标与固定决策说明

> 适用版本：0.4.2（当前仓库 HEAD）
> 整理时间：2026-09-24
> 相关位置：面板“高级设置（可选）”中的“调整任务目标”和“固定决策（可选）”

## 1. 结论

“任务目标”和“固定决策”解决的是同一类问题：**把跨轮必须稳定存在的信息，从会被裁剪的讨论历史中提出来，作为结构化字段每轮完整重发给模型**。

- 任务目标回答“这个任务最终要达成什么”，单条、可覆盖。
- 固定决策回答“哪些结论已经由人拍板、后续不得再动摇”，多条、可增删改、带来源轮次。

两者都是**提示层软约束**，不是硬校验：模型能看到它们，但代码不会因为模型违反而报错。真正会在应用前阻断越界改动的是修改预算 `budget`。

## 2. 两项配置的具体语义

| 配置项 | 数据结构与限制 | 默认值与保存方式 | 每轮如何生效 |
|---|---|---|---|
| 任务目标 `goal` | 单条字符串，最长 12000 字符 | 为空时，首轮提问自动用该问题的前 12000 字符填入（任务标题取前 60 字符）；之后改写需点“保存可选设置” | 每轮作为 `payload.task.goal` 全量发送；第二模型审查也会收到 `goal` |
| 固定决策 `decisions[]` | 最多 50 条，每条 ≤ 4000 字符；结构为 `{id, text, turnId, status: '用户确认'}`；不能为空；`turnId` 必须是真实存在的轮次 | 手动输入，或对某轮讨论点“编辑后固定”预填该轮原文；点“确认并固定”立即生效；“取消固定”移除；“编辑”后重新标记为“用户确认” | 每轮作为 `payload.task.decisions` 全量发送；指令明确要求把它当作本轮完整状态 |

## 3. 任务目标

### 3.1 目的

给模型一个不随对话漂移的“北极星”，说明这个任务要交付什么、边界在哪。

### 3.2 作用

HumanFlow 默认是“逐轮精简重建”：讨论历史只保留约 24000 字符，旧候选只保留目的、路径和数量。如果任务目标只存在于第一轮提问里，它可能被裁掉。目标字段独立携带，不受历史预算影响；持续线程被压缩后也依然保留。

### 3.3 意义

把“当前这一轮问什么”升级为“整个任务要什么”，避免模型只顺着最近一次追问作答、忘记最初目的。需要纠偏时直接修改目标并保存即可，不必重开任务，也不依赖模型自己从历史中找回意图。

### 3.4 边界

- 不限制文件范围或改动量，那属于修改预算。
- 不参与任何自动校验，写得含糊就会得到含糊的遵循。
- 第一轮之后在文本框中输入但未点“保存可选设置”，不会生效。

## 4. 固定决策

### 4.1 目的

把“讨论过的”“模型建议的”和“用户已经确认的”严格区分开。

### 4.2 作用

工程约定、接口边界、技术选型一旦确认就固定下来，防止后续轮次被模型重新推翻或顺手重构。每条决策保留 `turnId`，界面上的“来源”按钮能跳回它形成的那一轮，避免把 AI 的措辞误当成用户的决定。撤销固定后，下一轮不再携带；编辑则视为重新确认。

### 4.3 意义

它相当于一份轻量的“已确认决策台账”，让长期任务在历史被裁剪、线程被压缩的情况下仍然保有硬性上下文。保存代表用户确认，普通模型回复不会自动固定。

### 4.4 边界

- 这是提示层约束，不是门禁。现有代码在生成和应用阶段都不校验决策是否被遵守，模型若违反不会报错，仍需人工审查。
- 第二模型审查目前只带 `goal`、不带 `decisions`，见 [src/vscode/extension.cjs](../src/vscode/extension.cjs) 第 482 行。
- 数量上限 50 条，为空或过长会被拒绝。
- “取消固定”只是从当前生效列表移除，历史讨论正文仍保留在本地任务记录中。

## 5. 与其它每轮状态的关系

每轮上下文全量携带的是 `task.goal`、`task.decisions`、未解决的 `findings` 和实际 `outcomes`；历史讨论是**可裁剪**的，代码事实则每轮重新读取。模型收到的指令明确要求区分这三层：`task.goal/decisions/findings` 是本轮完整状态，已从列表撤销的固定决策不再生效，历史候选不等于已应用，固定决策的来源与确认状态不能混淆。

相关说明见 README：

- “默认逐轮精简重建”段落：目标、固定决策、未解决问题和实际应用结果另行携带。
- 0.4.0 工作区操作：固定决策可编辑、查看来源或取消固定；保存代表用户确认，普通模型回复不会自动固定。

## 6. 使用建议

- 任务目标写“最终交付物 + 范围边界”，不要写成一句模糊的口号。
- 固定决策写“已经确认、可执行、可验证的约束”，不要把模型回复原文直接粘贴进去。
- 模型回复中的好结论，先用“编辑后固定”改成自己的措辞再确认，这样来源轮次清晰、语义也更准确。
- 目标与决策冲突时，先改目标或撤销决策，再继续提问，避免把矛盾状态同时发给模型。
- 需要硬性限制改动范围时，使用“限制修改范围（可选）”，不要指望固定决策自动拦截。
