## 上下文与线程的实际边界

- 默认仍为逐轮重建。历史讨论预算为 **24,000 字符**，当前请求、目标、固定决策、未解决问题、结构化结果单独携带；完整请求超过 **300,000 字符**拒绝发送。字符不是 Token。
- 全部项目内脏缓冲区仍完整携带，不能静默退回旧磁盘内容。已保存的历史跟踪文件只优先附带当前关注文件和最近一次应用涉及的文件，其余按需重新读取。
- 所有原始讨论与候选在本地保留，不用界面折叠冒充上下文压缩。较早结构化应用记录保留文件、片段数和结果，最新记录保留精确片段。
- 持续线程必须由用户在“任务目标、固定决策与修改预算”里选择并保存。它以任务、根目录、提供方、模型、强度和联网配置隔离；每轮仍同步当前任务完整状态、当前缓冲区和实际应用结果。
- 持续线程使用 Codex 本地持久化记录，关闭客户端后可 resume；失效 ID 回退新线程。它不代表服务端只计算新增文本，也不代表不再发送历史 Token。
- 主动压缩等待整个压缩回合结束，而不是仅等待 `contextCompaction` 条目完成，避免下一轮触发 `ActiveTurnNotSteerable`。
- 没有收到压缩事件时不宣称已压缩；没有用量事件时显示未知。未测得真实提供方默认自动压缩阈值。
- 删除 HumanFlow 任务只删除插件的本地记录；实验持续线程还会在 Codex 自己的存储中留下记录，本功能不自动删除 Codex 历史。
- 本次不新增模型摘要引擎。固定决策加 Harness 压缩已经具备可测试路径；是否额外摘要留待真实长任务证据决定。

## 验证与测量

### 自动检查

- 51 项 Node 测试通过，覆盖候选、路径、部分应用、保存失败、版本、迁移、预算、只读请求、持续线程、压缩失败／超时／取消及工具安全。
- 15 个真实 VS Code 宿主场景通过，包含真实 WorkspaceEdit、撤销、Tasks 退出码、进程重启恢复，以及新增持续线程、草稿和阅读状态保存。宿主中的模型为 stdio 协议替身。
- 本地 Chromium：100 轮记录、旧正文按需挂载与搜索定位、目录、折叠、状态更新不抢阅读位置、草稿隔离、视图切换、消息版本缺口重同步、1080×800 和 380×740 布局检查通过。检查了两种尺寸截图。
- 真实 Codex CLI **0.156.1** 对隔离本机 Responses SSE 替身：主动压缩、设定阈值后的自动压缩、Token 事件、跨进程恢复、失效线程拒绝与新建成功。一次执行 8 次本机 HTTP 请求，其中观察到 1 次自动压缩。不是 DeepSeek 或 OpenAI 远程模型实测，也不能验证远程模型摘要的语义质量。
- 既有 DeepSeek 路由与自定义联网工具协议测试通过，使用本机 Responses 替身，不使用真实 API Key。

复现命令（已有 Node 和 Codex CLI，不安装依赖）：

```powershell
npm test
npm run test:extension
npm run test:ui
npm run test:harness
node scripts/test-deepseek-transport.mjs

```

UI 脚本会自动查找常见安装位置和 PATH 中的 Chromium/Chrome，也可通过 `HUMANFLOW_CHROMIUM` 指定；宿主脚本同样自动查找 VS Code，可用 `HUMANFLOW_VSCODE` 或命令行参数指定。两类脚本都使用隔离项目和用户配置；模型协议测试使用隔离 `CODEX_HOME`，不覆盖用户全局配置。

### 固定合成上下文

每轮含请求、解释和一个较大候选；另有当前未保存文件和固定决策。基线复现旧 60,000 字符逆序选择算法，并非对旧发布包逐字节抓包。优化结果的完整当前缓冲区和固定约束通过断言核对。

| 轮数 | 基线请求字符 | 优化请求字符 | 其中历史 | 当前文件及版本 | 其余状态 | 覆盖轮次 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 10 | 54,326 | 8,849 | 7,080 | 1,217 | 552 | 10 |
| 30 | 54,331 | 23,089 | 21,260 | 1,217 | 612 | 30 |
| 100 | 54,331 | 25,813 | 23,971 | 1,217 | 625 | 34 |

同一数据的持续线程新增请求为 1,741–1,742 字符，**不能用于估算服务端总输入或节省费用**。这些结果依赖候选大小、讨论长度和文件量，不承诺所有任务同等节省。

本机 Chromium 的一次 100 轮测试中，20 次状态更新（包括测试驱动往返）约 75 ms；不是跨设备性能保证。当前候选原生 Diff 入口位于“修改”视图：进入视图、勾选片段、预览；历史批次仅回看，不恢复应用资格。

## 保留的实验与未验证范围

1. **远程提供方**：未用 DeepSeek／OpenAI 远程账户做长上下文、缓存、费用或语义摘要质量测试。持续线程维持实验和默认关闭，真实服务不兼容可切回逐轮重建。
2. **联网**：已有工作区联网草稿随包保留且明确标注实验，默认关闭。DuckDuckGo 实际遇到验证码；Tavily 无真实 Key 验证；不将其作为稳定搜索承诺，也不作为 A/B/C 的依赖。开启联网时使用逐轮重建，避免复用已结束的工具取消信号。
3. **修改预算**：统计替换片段完整前后行数，可能比最小 Diff 保守；不做 AST 接口证明。依赖组是模型建议，不是自动证明。
4. **验证覆盖**：记录关联文件哈希，监听可见文件变化并保守作废；不声称完整捕获所有外部系统、副作用或被 VS Code 排除监听的路径。保存失败不自动回滚。自动凭据遮盖也不是完整秘密检测，发送前可核对预览。
5. **界面**：浏览器交互测试与真实扩展宿主测试分别完成；没有用真实远程模型在所有平台逐一手动验收。旧讨论初次只挂载最近 20 轮正文；已经展开的节点保留以保护阅读，不实施激进卸载。
6. **暂缓项**：第二套 Harness、多代理、向量索引、自动修复循环、自动回滚、复杂熟悉度画像继续按方案暂缓。调研中的运行中 steer、任务分支和检查点是后续建议，不混入本次稳定操作。
