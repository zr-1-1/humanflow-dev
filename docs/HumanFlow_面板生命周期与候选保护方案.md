# HumanFlow 面板生命周期与候选保护方案

实施日期：2026-10-03。

## 1. 问题与目标

隐藏、切换标签、缩小或最小化窗口属于展示变化，不应停止模型请求、清除候选或重新绑定关注点。关闭页面、替换候选、删除记录等操作需要说明影响，并允许用户取消和按操作类型记住“不再提示”。

排查发现的实际丢失路径：

- 已有面板再次执行打开命令时，自动绑定当前编辑器选区，导致旧候选失效。
- 新请求一开始就清空上一批候选；取消、超时或响应校验失败时无法继续处理旧候选。
- 原生标签关闭通知立即中断请求并重置客户端，没有确认与页面恢复。
- 候选勾选、依赖确认、文件位置和片段展开状态只保存在页面变量，页面销毁后丢失。
- 输入区在发送消息后立即清空；宿主拒绝或用户取消替换确认时，尚未开始的请求也会丢草稿。

## 2. 本次已实现

### 2.1 展示变化与关闭分开

- 继续使用 `retainContextWhenHidden: true`；隐藏、缩小与切换标签不调用取消或清空逻辑。
- 打开已有任务只唤起页面；自动绑定选区限于尚无关注点、讨论和候选的新任务。后续关注点变化使用明确按钮。
- 唤起已有页面保持原分栏。已有可见页面显示确认时不再移动编辑器列。
- 文档通知先比较全文内容版本；没有实际内容变化的通知不会取消请求或使候选失效。
- 源代码实际变化仍会停止与旧代码有关的生成，并禁止应用旧候选；候选原文保留供阅读，不能把旧版本片段直接写回新代码。

### 2.2 关闭保护

页面顶部增加“关闭面板”按钮，在关闭前显示模态弹窗。取消时继续保留页面、请求、候选和草稿；确认关闭后才停止模型请求和验证。候选与草稿在同一扩展宿主内保留，重新打开可继续审查。

**原生叉号的接口边界**：普通 `WebviewPanel` 只有 `onDidDispose` 关闭后通知，公开稳定接口没有可否决的关闭前事件。因此原生叉号会先销毁页面，扩展随即恢复一个保护页面并显示确认；此时宿主中的请求和候选尚未取消或清除。选择返回可继续工作；确认后才停止请求并完成关闭。可能看到页面短暂关闭后恢复。

扩展停用、窗口退出清理设置关闭标志并取消待确认操作，避免清理期间重建页面。该确认针对 HumanFlow 页面，不作为整个 VS Code 窗口关闭的阻断机制。

接口依据：[WebviewPanel API](https://code.visualstudio.com/api/references/vscode-api#WebviewPanel)、[Webview 生命周期与隐藏上下文](https://code.visualstudio.com/api/extension-guides/webview)。

### 2.3 替换、失效与删除

- 新请求替换候选前确认；旧候选在新请求期间继续保留，暂时禁止应用。成功接收并完成代码版本校验后，才提交新候选。
- 新请求失败、超时或人工取消时，恢复旧候选对应的批次、引用、基线和草稿引用。真实代码变化时保留原文，但继续禁止应用。
- 清除候选、采用草稿、切换任务、更新关注点、切换模型服务、删除任务和取消固定决策前分别说明影响。
- 同一窗口新建或切换任务时保留原任务候选；恢复任务时重新校验当前代码版本，无法通过则只读保留。
- 清除当前候选保留讨论与历史批次；删除任务明确说明本地讨论、问题、验证及候选记录将删除，无法撤销。两者都不会删除业务文件。
- 保留上一批候选时，批次状态按实际候选展示，不因最新请求失败而显示成没有候选。

### 2.4 草稿与阅读状态

- 发送使用请求 ID，宿主真正开始请求后才清空对应草稿与问题引用。确认取消或请求被拒绝时保留输入。
- 草稿输入及时发送给宿主；候选勾选、依赖确认与文件位置立即保存，普通滚动等状态继续合并保存。
- 页面隐藏、导航、关闭按钮和确认回复前补发当前草稿与 UI 状态。
- 片段展开状态具有稳定批次 ID；恢复页面按任务和批次恢复勾选、展开、依赖确认及位置，防止旧批次状态套到新批次。

## 3. 确认偏好

弹窗包含“此类操作以后不再提示”。只有确认继续且勾选时才保存；取消不会关闭未来提示。保存失败时保持操作未执行，允许取消勾选后重试。

偏好是个人用户设置，默认全部开启；按类型分开，关闭提示不会连带禁用删除任务提示：

| 设置 | 适用操作 | 默认值 |
| --- | --- | --- |
| `humanflow.confirmClosePanel` | 关闭面板 | `true` |
| `humanflow.confirmDiscardCandidate` | 清除当前候选 | `true` |
| `humanflow.confirmReplaceCandidate` | 发送替换请求、采用草稿 | `true` |
| `humanflow.confirmChangeContext` | 切换任务、关注点和模型服务 | `true` |
| `humanflow.confirmDeleteTask` | 删除任务记录 | `true` |
| `humanflow.confirmDeleteContent` | 取消固定决策 | `true` |

面板“模型与任务设置 → 扩展设置与配置文件”提供“恢复操作确认提示”；命令面板也可运行 `HumanFlow: 恢复操作确认提示`。超时设置仍允许项目覆盖，确认偏好使用用户级应用作用域。

确认由宿主持有并绑定独立请求 ID 和任务 ID；过期页面或其他任务的回复无法授权新操作。确认等待期间阻止其他会改变任务或候选的操作，继续接受草稿、UI 状态和语言更新。

## 4. 验证

离线测试覆盖确认等待、取消、不再提示的类型隔离、错误任务和过期回复拒绝、偏好保存失败、恢复提示、重开保留候选、无内容变化通知、切换任务、代码变化和请求取消。

Chromium 使用真实原生 `<dialog>` 验证焦点、Esc 取消、重复消息不重置勾选、320 像素窄窗口，以及完全重建页面后从宿主状态恢复草稿、候选勾选、片段展开与依赖确认；保留原有语言切换和大量问题记录回归。

真实 VS Code 测试使用隔离配置与本地协议替身，验证隐藏期间请求继续、重新唤起不重绑关注点、原生叉号恢复确认、确认前不取消、返回继续、确认关闭后重开、替换失败及实际候选应用，并验证扩展进程重启后的历史恢复。没有调用真实模型。

## 5. 后续优化建议与当前边界

1. **待审查候选跨进程保存**：将候选、基线哈希、草稿正文及操作记录写入专用版本化本地存储，原子保存并限额；重启后逐文件校验，通过后恢复审查。当前运行时候选与草稿编辑器引用只在同一扩展宿主内保存；重启后可查看历史候选原文，需重新生成后应用。
2. **候选撤销与归档**：为显式清除增加短期回收区和撤销入口，提供复制或导出候选。暂不自动删除历史、草稿文档或业务文件。
3. **关闭前交互能力评估**：若必须在 VS Code 原生叉号销毁页面前弹窗，可评估带有脏状态和备份机制的 Custom Editor；需要考虑保存/放弃/取消语义及恢复文件的体验，避免将任务误当成业务文件修改。
4. **会话保存可见性与限额**：展示本地保存状态，候选和草稿按任务计量；长期未使用的运行时缓存可经明确操作归档，不能因窗口宽度、隐藏时间或普通失焦自动清除。

优先推进跨进程候选和草稿保存，再补撤销/导出；本次先保证展示变化不丢状态、显式删除可确认、异常替换保留旧候选。
